# 02.2 — Sélection paiement

## Page Metadata

| Property | Value |
|----------|-------|
| **Scenario** | 02: Vivien encaisse une vente |
| **Page Number** | 02.2 |
| **Platform** | Tablette / téléphone Android partagé sur comptoir |

## Overview

**Page Purpose:** Choisir le mode de paiement, saisir le montant reçu, voir la monnaie calculée automatiquement — sans erreur, sans calcul mental devant la cliente.

**Entry Context:** Aïcha vient de taper "Encaisser • 3 500 F" depuis 02.1. La cliente tend son billet de 5 000 F.

**Exit Action:** Tape **"Valider le paiement"** → Confirmation facture (étape 02.3).

**Navigation:**
- **Breadcrumb desktop:** `Boutique > POS > Paiement`
- Mobile : back button (retour panier 02.1) + titre "Paiement"

**On-Page Interactions (storyboard items):**
- **Tap mode** (Cash · Wave · Orange Money · Crédit) — Cash sélectionné par défaut
- **Pavé numérique** pour saisir le montant reçu (Cash uniquement)
- **Suggestions montants ronds** (4 000 / 5 000 / 10 000 / Compte exact)
- **Calcul auto monnaie** dès la saisie
- Wave / OM → champ numéro client (optionnel) + bouton "Confirmer reçu"
- Crédit → sélection client CRM (sortie de scope, géré scénario 07)
- Bouton **"Valider le paiement"** sticky bottom

**Contenu clé:**
- Récap panier compact en haut (2 articles · 3 500 F)
- 4 tuiles modes de paiement avec icônes colorées
- Zone saisie montant avec gros chiffre + monnaie en surbrillance verte
- Pavé numérique tactile pour gros doigts (touches 56px+)
- CTA primaire pleine largeur

## States à maquetter

1. **Default M** — Cash sélectionné, montant 5 000 F saisi, monnaie 1 500 F affichée en vert
2. **Wave M** — Wave sélectionné, champ numéro client visible, montant pré-rempli
3. **Pavé ouvert M** — focus sur le champ montant, pavé numérique grand format
4. **Erreur montant insuffisant M** — saisie 3 000 F < 3 500 F, message erreur rouge
5. **Default Tablette/Desktop** — layout 2 colonnes : modes à gauche, récap+monnaie à droite
