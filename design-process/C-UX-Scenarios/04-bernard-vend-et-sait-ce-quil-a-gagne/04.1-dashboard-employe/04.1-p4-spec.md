# 04.1 — Identification Vendeur · Phase 4 UX Spec

## Identité de la page
- **Nom** : Identification Vendeur (PIN)
- **Scénario** : 04 — Bernard Vend et Sait Ce Qu'il a Gagné
- **Persona** : Koné Tiéba (vendeur employé de Bernard)
- **Plateforme** : Desktop (PC boutique) — mode kiosque plein écran
- **Style** : Modern SaaS + Professional/Corporate

## Décision produit clé

Le rôle "Vendeur" n'a pas accès au dashboard. Il arrive directement sur le POS Catalogue après identification. Le dashboard (KPIs, CA) est réservé au rôle "Propriétaire". Les rôles sont définis dans le template intégrateur.

---

## Architecture PIN révisée — 3 cas

### Cas 1 — Caissier / Commercial (compte Supabase propre)

L'employé a son propre compte Supabase (email + mot de passe). Il s'est déjà authentifié en ouvrant l'app. **Aucun PIN n'est demandé à l'arrivée sur le POS.**

Flux :
1. Connexion Supabase (email + mot de passe) — écran de login standard
2. Arrivée sur le POS → SessionGuard vérifie le profil → session ouverte directement
3. **Auto-verrouillage après N minutes d'inactivité** (composant B — voir ci-dessous)

Le minuteur d'inactivité est configurable par le propriétaire dans Paramètres → Sécurité (valeurs : 5 / 10 / 30 min).

### Cas 2 — Propriétaire (terminal partagé)

Le propriétaire (Bernard) est le compte Supabase connecté sur l'appareil. L'appareil est partagé entre plusieurs vendeurs. **Le PIN permet d'identifier quel vendeur opère le terminal à chaque prise de poste.**

Flux :
1. L'app démarre avec le compte Supabase du propriétaire déjà connecté
2. Arrivée sur le POS → SessionGuard détecte `role == 'owner'` → affiche le **composant A : EmployeePinScreen**
3. Le vendeur sélectionne son profil + saisit son PIN (4 chiffres)
4. Validation → session ouverte sous le nom du vendeur identifié
5. En fin de poste : fermeture de session → retour à l'**EmployeePinScreen** pour le prochain vendeur

Les profils vendeurs (nom, PIN, couleur) sont des profils locaux gérés dans **Paramètres → Équipe & PINs** (pas des comptes Supabase).

### Cas 3 — Manager

Le rôle `manager` **n'a pas accès au POS**. Il accède uniquement au backoffice (vue restreinte). Le SessionGuard ne doit pas afficher d'écran PIN pour un manager — il doit refuser l'accès au POS avec un message clair.

Impact code : retirer `manager` de la condition `needsPin` dans `session_guard.dart`.

---

## Composant A — EmployeePinScreen (terminal partagé / propriétaire uniquement)

**Quand** : `role == 'owner'` et aucun vendeur sélectionné (`selectedEmployeeProvider == null`)

### Vue A1 — Sélection vendeur
- Fond sombre plein écran (mode kiosque, `Colors.blueGrey.shade900`)
- Wordmark Scalario + nom boutique + date du jour
- Grille de cards vendeurs (avatar couleur + prénom)
- CTA "Continuer →" (actif uniquement si un vendeur est sélectionné)
- Lien "Gérer l'équipe" (accès rapide pour le propriétaire, navigue vers TeamPinScreen)

### Vue A2 — Saisie PIN
- Rappel du vendeur sélectionné (avatar + nom + lien "Changer")
- 4 points PIN (remplis au fur et à mesure)
- Clavier numérique (auto-valide à 4 chiffres)
- Erreur si PIN incorrect (secousse + message "PIN incorrect")
- Succès → session ouverte → POS Catalogue

### Navigation sortante
PIN validé → **04.2 POS Catalogue**

---

## Composant B — SessionLockScreen (verrou inactivité, tous les rôles POS)

**Quand** : N minutes sans interaction (configurable, défaut 10 min)

**Rôles concernés** : `cashier`, `commercial` (leur propre PIN Supabase), `owner` sur terminal partagé (PIN local du vendeur actif)

### Comportement
- Un `Timer` se réinitialise à chaque interaction utilisateur (tap, scroll, saisie)
- Après N minutes d'inactivité : superposition de l'écran de verrou par-dessus le POS (opaque, fond sombre)
- L'écran affiche : avatar du vendeur actif + "Session verrouillée" + champ PIN

### Vue Verrou
- Fond sombre plein écran (non dismissable par back/tap extérieur)
- Avatar + nom du vendeur actif
- Sous-titre : "Saisissez votre PIN pour reprendre"
- 4 points PIN + clavier numérique
- PIN validé → l'écran de verrou disparaît, le POS reprend là où il était
- Lien "Ce n'est pas moi" → efface l'employé actif → retour à EmployeePinScreen (cas terminal partagé) ou déconnexion (cas compte propre)

### Configuration
- Réglage dans **Paramètres → Sécurité** (owner only)
- Valeurs : Désactivé / 5 min / 10 min / 30 min
- Provider : `sessionLockTimeoutProvider` (StateProvider<int?>, null = désactivé)

## Impact sur session_guard.dart

```dart
// Avant (incorrect — cashier/commercial voient le PIN screen)
final needsPin = profile.role == 'cashier' || profile.role == 'commercial';

// Après (correct — PIN partagé uniquement pour owner sur terminal partagé)
final needsPin = profile.role == 'owner';
// Manager : refus d'accès (déjà géré par canAccessScreen)
```

## Profils locaux vs comptes Supabase

| Type | Stockage | Créé par | Usage |
|------|----------|----------|-------|
| Profil vendeur local (EmployeeProfile) | SharedPreferences | Owner dans Paramètres → Équipe & PINs | Identification sur terminal partagé (Cas 2) |
| Compte Supabase (cashier/commercial) | Supabase Auth | Owner dans Paramètres → Équipe | Connexion individuelle (Cas 1) |

Les deux systèmes coexistent. Un vendeur peut avoir les deux (compte Supabase + profil local), mais dans ce cas il utilisera son compte Supabase pour se connecter — le profil local n'est utile que sur le terminal du propriétaire.
