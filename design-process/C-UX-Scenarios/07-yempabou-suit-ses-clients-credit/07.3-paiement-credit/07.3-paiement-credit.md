## Overview

**Page Purpose:** Enregistrer un paiement reçu d'un client en crédit — affecter le montant aux crédits ouverts (auto FIFO ou manuel), choisir le mode de paiement, imprimer un reçu.

**Entry Context:** Depuis Fiche client (07.2) → tap "Enregistrer un paiement". OU depuis POS bouton "Paiement crédit".

**Exit Action:** Tape **"Valider et imprimer reçu"** → succès → retour Fiche client avec solde mis à jour + toast "Paiement enregistré, reçu imprimé". ✓

**Navigation:**
- **Breadcrumb desktop:** `Boutique > Clients > [Nom] > Paiement crédit`
- Mobile : modal plein écran ou bottom sheet

## Sections / Layout

### 1. Header context
- Nom client + avatar
- **Solde dû actuel : 12 500 F** (gros)

### 2. Saisie montant reçu (focus auto)
- Input numérique grand format
- Suggestions rapides : "Solde total" (12 500), "Moitié" (6 250)
- Validation : pas de montant > solde (ou autoriser avec message "génère un avoir")

### 3. Mode de paiement
- Boutons : Cash (default) / Wave / Orange Money
- Si Cash : saisie montant donné → calcul monnaie

### 4. Affectation aux crédits (liste collapsible)
- Liste des crédits ouverts triée du plus ancien au plus récent
- Mode AUTO (FIFO) : montant réparti automatiquement
- Mode MANUEL : checkboxes + montant par crédit
- Affichage en live de comment le paiement va être réparti

### 5. Récap pré-validation
- Montant : 8 000 F
- Mode : Cash
- Affecté à : 1 crédit (vente du 12/03)
- Nouveau solde : 4 500 F
- Reçu sera imprimé : ✓

### 6. Actions sticky bottom
- Bouton secondaire "Annuler"
- Bouton primaire **"Valider et imprimer reçu"**
- Toggle "Imprimer reçu" (default ON)

## On-Page Interactions

- **Saisie montant** → recalcul live affectation + nouveau solde
- **Switch mode paiement**
- **Toggle auto/manuel** affectation
- **Édition manuelle** des montants par crédit
- **Toggle impression** reçu

## Validation

- Montant > 0 obligatoire
- Mode paiement obligatoire
- Si mode Cash : montant donné ≥ montant reçu

## Pourquoi cette page est critique

- C'est le moment où l'argent rentre — zero ambiguïté tolérée
- Le reçu imprimé = preuve pour le client + lock-in pro
- L'affectation FIFO doit être transparente (Yempabou doit voir où va son argent)
