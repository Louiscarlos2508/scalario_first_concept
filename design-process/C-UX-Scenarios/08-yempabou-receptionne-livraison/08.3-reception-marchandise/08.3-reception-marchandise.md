## Overview

**Page Purpose:** Saisir une réception de marchandise ligne par ligne — comparer commandé vs reçu, ajuster les quantités, marquer écarts/avaries, valider → stock incrémenté + facture archivée.

**Entry Context:** Depuis Fiche fournisseur (08.2) → "Réceptionner livraison". OU depuis liste commandes en attente.

**Exit Action:** Tape **"Valider la réception"** → confirmation modale → succès → retour Fiche fournisseur avec toast "Réception enregistrée, stock mis à jour". ✓

**Navigation:**
- **Breadcrumb desktop:** `Boutique > Fournisseurs > [Nom] > Réception`
- Mobile : back + titre "Réception JJ/MM"

## Sections / Layout

### 1. Header context
- Fournisseur (avec lien)
- Date commande
- Bon de commande N°
- Statut actuel : `En attente` / `Partielle`

### 2. KPI strip (live)
- Lignes commandées : 12
- Lignes reçues : 8 / 12
- Total commandé : 145 000 F
- Total reçu (en cours de saisie) : 122 000 F

### 3. Liste lignes à réceptionner
Pour chaque ligne :
- Photo + nom produit
- Qté commandée (read-only)
- **Qté reçue** (input éditable, default = qté commandée)
- Différence calculée en live (vert OK, rouge écart)
- Champ "Motif écart" (visible si écart) : `Manquant`, `Avarié`, `Refusé`, `Autre`
- Prix unitaire (éditable si différent du devis)
- Subtotal calculé

### 4. Frotte automatique (toggle)
- Si activé : applique le taux de frotte du produit (% reçu défalqué automatiquement)
- Affichage en live de la qté entrée en stock (= reçu - frotte)

### 5. Pièces jointes
- Photo du bon de livraison (caméra)
- Photo de la facture
- Numéro facture fournisseur

### 6. Validation sticky bottom
- Récap : total reçu, total écart, nb lignes ajustées
- Bouton primaire **"Valider la réception"**
- Toggle "Réception complète" / "Réception partielle"

## On-Page Interactions

- **Saisie qté reçue** → recalcul live diff + total
- **Toggle frotte** → recalcul stock entré
- **Saisie motif** si écart
- **Photo facture** depuis caméra
- **Action "Tout reçu"** → remplit toutes les qtés avec qté commandée
- **Réception partielle** → garde la commande ouverte pour solde

## Validation

- Au moins 1 ligne avec qté reçue > 0
- Motif obligatoire si écart négatif
- Photo facture optionnelle mais recommandée

## États

- **Première réception** → toutes lignes vides, default = commandé
- **Réception partielle** (commande déjà partiellement reçue) → reste à recevoir affiché
- **Validation en cours** → loader + désactivation boutons

## Différences vs PurchaseOrderDetailScreen actuel

- **Recadrer UX sur le geste de réception** (pas vue détail commande)
- **Diff commandé/reçu en live** (visualisation rouge/vert)
- **Toggle frotte** intégré (différenciateur Phase 1)
- **Capture photo facture** intégrée
- **Bouton "Tout reçu"** pour gain de temps
- **Mode partielle** clair

## Données impactées

- PurchaseOrder mis à jour (statut, items reçus)
- Stock incrémenté (StockMovement de type RECEPTION)
- Frotte calculée (StockMovement de type FROTTE si activé)
- Facture archivée (Document lié)
- Mouvement comptable (Expense créé)

## Pourquoi cette page est critique

- C'est l'autre point d'entrée du stock (avec inventaire)
- Toute erreur ici = stock faux + comptes faux
- Doit gérer les écarts de manière transparente
- La photo facture = preuve tangible (différenciateur vs cahier)
